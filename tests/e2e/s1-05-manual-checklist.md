# S1-05 手工端到端验收

在仓库根目录运行 `bun run dev`，打开 <http://localhost:4173/lessons/s1-05/>。如需从头开始，删除浏览器本地存储键 `csp-cpp-s1-05-progress-v1` 后刷新。

## E2E-S1-05-01 引导任务推进

1. 在任务 1 为“60 分算不算合格”选择 `if (score >= 60)`，为“优秀、合格、需要复习”选择 `if / else if / else`。先故意选一个错误判断。
2. 在任务 2 依次点击“先问 90 分？”“再问 60 分？”“输出合格”。尝试跳过 90 分直接点 60 分。
3. 在任务 3 先选择一个错误说法，再选择“这会把 60 装进 score，条件几乎总是真”，以及“if (score == 60)”；确认完成后提示进入任务 4“亲手补齐两行条件”。

**预期：** 每一步都显示即时文字反馈；下一任务仅在前一任务完成后点亮；错误选项解释为什么判断或符号不对；分数卡片从“还没开始提问”变为“60 >= 90 不成立”，再变为“60 >= 60 成立”，再变为“合格”；页面标明必会、建议掌握和拓展；正确完成会出现奖励提示，音效关闭时仍有完整视觉反馈。页面不运行学习者提交的 C++，也不加载视频。

补充：点击尚未点亮的任务或跳过“先问 90 分？”直接点击 60 分时，页面必须解释当前缺少哪一步，不能无反馈。

## E2E-S1-05-02 亲手补齐两行条件

1. 完成前三个任务后进入“任务 4：亲手补齐两行条件”，确认两行 `if` / `else if` 各有一个输入框，以及“检查这两行”“看提示”“参考代码”“重写一遍”四个按钮。
2. 第一空故意写 `score > 90`，第二空写 `score >= 60`，点击“检查这两行”。
3. 把第一空改成 `score = 90` 再检查一次，然后改成 `score >= 900` 再检查一次。
4. 点击“看提示”，再点击“参考代码”展开和收起。
5. 两空分别写成 `score >= 90` 和 `score >= 60`，点击“检查这两行”。
6. 完成后点“重写一遍”，确认两行清空、可以重新作答；刷新页面确认草稿与完成状态。

**预期：** 每一步都有即时文字反馈，并通过状态区域向辅助技术说明结果。用 `>` 时提示优秀线和合格线都包含等于；用单个 `=` 时提示那是赋值而不是比较；写 `900` 时提示数字写错，不能把 `900` 当作 `90` 放行；用中文标点时提示改用半角。检查失败时输入框有可见的错误样式，学习者可看提示、看参考代码或重写，不会卡住。两行都写对后任务 4 标记完成、任务 5 点亮并给出奖励反馈；音效关闭时仍有完整视觉反馈。页面只按文字规则检查条件，不编译、不执行学习者写的 C++。

补充：在输入框里用左右方向键移动光标时，不应触发任务切换。

## E2E-S1-05-03 随机小测与解析

1. 进入“任务 5：随机小测”，确认显示本次试卷标识和 3 道选择题。
2. 不作答时确认提交按钮不能提交；选择三题答案后提交。
3. 阅读每题解析和总分。
4. 点击“换一套题”。

**预期：** 单次试卷题目不重复；每题都把检查目标绑到本课学习目标原文、另起一行写出本题检查、四个选项、一个正确答案和解析；选择题数量多于非选择题；提交后显示逐题正误与得分；换题后试卷标识变化且不保留上一套答案。题库来源为本课 course-plan / 自编，并标记待人工审校。

## E2E-S1-05-04 恢复与降级

1. 完成任意任务或选择部分小测答案后刷新页面。
2. 回到当前任务，确认判断选择、60 分提问流程、任务 4 的条件草稿和答案恢复。
3. 在禁止站点存储的浏览器环境中重复一次操作。

**预期：** 正常环境能恢复任务、条件草稿、试卷与答案；存储不可用时页面明确说明“刷新后不会恢复进度”，页面不会卡住或伪造保存成功。

## E2E-S1-05-05 常见问题解惑

1. 在任务 1 点击带虚线的 `if` 或 `else if`。
2. 确认侧栏出现基础解释、一句“现在记住”和至少一个外部链接。
3. 关闭后进入任务 3，点击 `==` 或 `=`；再到任务 4 确认 `==` 和 `=` 同样可以点开。
4. 再点右上角“常见问题”，切换到 `&& 并且`。

**预期：** 解释只用初学者能懂的话；不要求背完整运算符表；外部链接在新标签打开。词条以小卡片出现，不挡住任务按钮；点遮罩、“关闭”或“继续学习”后可立刻继续做题。

## 自动化复验记录

E2E-S1-05-02 中的手写填空部分可以在真实浏览器中自动重跑一遍，不需要人工点击：

```bash
bun run e2e:s1-typed
```

脚本会自行启动开发服务器（`bun scripts/dev.ts`）和无头 Chrome，结束后关掉自己启动的进程并删除临时配置目录。它需要本机装有 Chrome；若换成别的可执行文件路径，用 `CSP_E2E_CHROME` 指定。它不属于 `bun test`：断言依赖真实浏览器渲染，属于体验验收而不是单元测试。`bun run e2e:s1-typed` 一次覆盖 S1-02 至 S1-08 七课（115 项检查，本课 17 项），`bun run e2e:typed` 覆盖全部 39 节已迁移课（659 项检查）；`CSP_E2E_LESSONS=s1-05 bun tests/e2e/s2-typed-cdp.ts` 可以只跑本课。

自动化覆盖的部分：输入框等宽字体与移动端防干扰属性、脚手架留两空（if 与 else if 各一行）且没有 textarea、打开页面时输入框还没有出现、先走完三步提问演示，再把任务 3 的 `=` / `==` 与括号两处都选对，输入框才出现、逐字符真实键盘输入会写进草稿、提示与参考代码兜底、重置会把输入框里看得见的内容和草稿一起清掉、作答正确后进入下一个任务、刷新后草稿与完成状态恢复、输入内容原样保留且不会被当成 HTML 或正确答案；抽到的题把检查目标绑到本课学习目标原文并保留本题检查。

三种失败路径（自动化逐条核对过）：空提交会提示“先写下你的答案”；整行都是全角符号时逐个指出该换成半角；第三种是写错语义 —— 写成 `score > 90`（丢掉等于），会给出对应指正且不判定完成。

重置按钮本轮修过：以前多数课只清掉状态，输入框里看得见的旧字会留下（聚焦状态下尤其明显），现在内容与对错样式一起清；本轮把 S1 里还漏这条的七课补齐，S1-05 本来就已经清得干净，作为对照保留。

仍需人工确认的部分：窄屏排版、键盘焦点观感、音效听感，以及上面对应场景里没被自动化覆盖的步骤。
