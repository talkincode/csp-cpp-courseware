# 整课推进手工端到端验收（S1-02 至 S5-08）

这份清单管的是「一整节课能不能从 0 / N 走到 N / N」：走完四个任务、四个任务都真的动过手、跳步会被拦住、
进度只留在浏览器本地，最后小测本身也能量。它和每课自己的 `sN-NN-manual-checklist.md` 不互相替代——
那边验「这一个空位本身」（出现时机、全角符号、语义写错、提示与参考代码兜底、重置、草稿恢复），
这边验「这节课整段路走得通不通」。

S1-01 不在这份清单里：它由 [`s1-01-manual-checklist.md`](./s1-01-manual-checklist.md) 的八个场景单独复验，粒度更细。

## 前置条件

在仓库根目录运行 `bun run dev`，从 <http://localhost:4173/> 进入任意一课。需要从头开始时删除该课的本地存储键
`csp-cpp-sN-NN-progress-v1` 后刷新，或按下面每个场景里的说明做。

## 每课固定复验的 19 项

前十一项在整段路上量，后面八项在小测面板里量：

1. 打开页面时是 `0 / N 已推进`，第一步面板可见。
2. 一上来点最后一步不会跳过去，并说明要先完成前一个任务。
3. 在真实浏览器里逐个任务点击后，推进到 `N / N 已推进`。
4. 每一步都真的走过了，没有靠跳过凑满进度。
5. 完成时给出可见的完成文案。
6. 没做完之前，页面不会把学习者提前引到下一课（继续学习入口此时是隐藏的）。
7. 完成后自己揭开继续学习入口：链路指向 `courseData` 里的下一课，链接能真的打开（不是死链），
   文案里写明下一课是 `Sx-xx` 与标题；最后一课换成课程收尾出口，指回课程路线且不再指向任何兄弟课目录。
8. 每道小测题绑到本课学习目标原文，并另起一行给出本题检查。
9. 一次抽出的三道题互不重复且都是选择题。
10. 没答完不能提交，并说明还差几题。
11. 答满才放行提交。
12. 提交前不给解析，提交后逐题给出解析。
13. 提交后给出得分、标出正确选项并锁定作答。
14. 没考住时按学习目标汇总错题、指回本节讲解，且不倒退进度。
15. 如实写明题目已通过校验。
16. 换一套题会换试卷标识，题库本身不动。
17. 刷新后进度仍为 `N / N`（学习进度只保存在浏览器本地）。
18. 进度写在本人专属的本地键里，没有提交到别处。
19. 清掉本地存储后回到 `0 / N`，页面不依赖任何服务端状态。

## E2E-FLOW-01 跳步与解锁顺序

1. 打开一课（例如 S3-07），不要做任何操作，直接点步进轨道上最后一格。
2. 再做第一个任务，然后回头看步进轨道和「`N` / `4` 已推进」这一行。

**预期：** 第 1 步不会跳到最后一格，页面留在当前任务并说明要先完成前一个任务；第 2 步完成后，被解锁的下一格
会自己亮起来，进度数字同步加上去。任何一次跳步或完成都要有即时可见反馈，状态区域同时向辅助技术说明结果。

## E2E-FLOW-02 整课走完一遍

1. 按任务顺序把这一课做完：选择题选到对为止、把空位补对、把演示按钮按到演示走完。
2. 四个任务全部完成后看完成条与小测面板。

**预期：** 进度停在 `N / N 已推进`，完成条给出与本节目标对应的具体文案（不是「太棒了」这类空话）。
故意在某个互斥选项上先点错的答案时，错的选项会被标出并解释为什么不对，改选正确答案后仍然能完成任务——
选错不会把已经做对的答案一起冲掉。

## E2E-FLOW-03 小测的通过与否两条路径

1. 点「换一套题」，确认试卷标识换了、上一套的答案没有留下。
2. 不作答时看提交按钮，再只答一题、再答满三题，分别看按钮文案与是否可提交。
3. 全部选对提交；再点「换一套题」，这次故意全部选错并提交。

**预期：** 没答完时按钮写明还差几题且点不动；答满才放行。提交前看不到解析，提交后每题给出正误、解析与得分。
全部选对时给出通过文案；全部选错时给出 `本次答对 0/3`，并按本课学习目标原文汇总「错题集中在：……」、
指回本节继续讲解，且**不倒退已经学过的进度**。两种情况下题目都标着已通过校验，页面不运行学习者提交的 C++。

## E2E-FLOW-04 进度只在本地

1. 完成若干任务后刷新页面。
2. 在禁止站点存储的浏览器环境里重复一次操作，再清掉该课的本地存储键后刷新。

**预期：** 正常环境刷新后任务与答案恢复；存储不可用时页面明确说明「刷新后不会恢复进度」，互动不中断、
不伪造保存成功；清掉本地存储后回到 `0 / N`，这一课不依赖任何服务端状态。

## E2E-FLOW-05 课后继续学习入口

1. 打开一课（例如 S2-06），不要做任务，先看页面下方有没有「继续学习」入口。
2. 把这一课做到 `N / N 已推进`，再看同一处。
3. 点开入口里的链接，确认打开的是下一课；回到路线页换到 S5-08，做完最后一课再看同一处。

**预期：** 没做完时入口是隐藏的，页面不会把学习者中途引走。完成后入口自己出现，写明下一课是
`Sx-xx` 与课名、先练的那件事，链接直接打开下一课（不是死链、不是回到目录页），并再次说明进度只保存在
这台设备的浏览器里。最后一课没有下一课，入口改成课程收尾：说明五阶段 40 课已经走完、建议怎么复盘、
题目与解析已通过校验，并指回课程路线；这里不给成绩评定、证书或任何能力认证的说法。
入口是普通链接，可以用 Tab 聚焦、回车打开，键盘用户不依赖鼠标。

## 自动化复验记录

上面 E2E-FLOW-01 至 -05 里可以被脚本确定下来的部分，可以在真实浏览器中自动重跑一遍：

```bash
bun run e2e:flow        # 全部 39 节已迁移课，741 项
bun run e2e:flow:s3     # 只跑第三阶段八课，152 项
CSP_E2E_LESSONS=s3-07 bun tests/e2e/flow-cdp.ts   # 只跑一课，19 项
```

脚本自行启动开发服务器（`bun scripts/dev.ts`）与无头 Chrome，结束后关掉自己启动的进程并删除临时配置目录。
它需要本机装有 Chrome；换成别的可执行文件路径用 `CSP_E2E_CHROME` 指定，端口冲突时用 `CSP_E2E_PORT` /
`CSP_E2E_CDP_PORT`，要复用已在运行的服务用 `CSP_E2E_ORIGIN`。它不属于 `bun test`：断言依赖真实浏览器渲染，
属于体验验收而不是单元测试。

## 脚本为什么这么驱动

这一课的答案表（空位 id、正确写法、判断按钮、第二空位）只有一份，放在 [`lesson-flows.ts`](./lesson-flows.ts)，
`flow-cdp.ts` 与 `s2-typed-cdp.ts` 共用，改一处两边同时生效。脚本不去猜每课问什么，而是照着页面自己的规矩走：

- 进度以页面自己的 `unlockedStepCount()` 为准，总步数取步进轨道的 `data-step` 数量；
- 空位只在**已经露出来**（`offsetParent !== null`）时才填。页面本来就把某些空位藏到前面的任务做完之后
  （例如 S1-03 先选对公式才露出平均分的填空），照着看得见的东西驱动，才不会量出学习者根本遇不到的状态；
- 互斥选项按组走：同一个父元素下的一组按钮，点一个、看这组有没有出现 `is-correct`，出现了就换下一组。
  不能不看对错地全点一遍——有些课会先把错的答案写进状态再判对错，全点一遍会把已经选对的覆盖成错的；
- 小测的正确答案从页面自己的 `questionPool` 里读，所以题库换了脚本不用改。

## 仍需人工确认的部分

脚本只能证明「路走通了、话说清了」，下面这些还得人来看：窄屏与移动端排版、键盘焦点观感、音效听感、
`prefers-reduced-motion` 下的动效表现，以及 E2E-FLOW-01 至 -04 里没被断言覆盖的步骤。
