# 手工端到端验收脚本

本项目保持零依赖静态运行，因此首版用可重复的手工端到端脚本覆盖浏览器交互。执行时记录浏览器和日期；若任何预期不成立，不应把相关能力标为完成。

单课场景可以用真实浏览器自动重跑一遍，不需要人工点击：

- `bun run e2e:s1-01`：自动启动开发服务器与无头 Chrome，复验 [`s1-01-manual-checklist.md`](./s1-01-manual-checklist.md) 的八个场景（88 项断言），结束后自行清理。它需要本机装有 Chrome，且不属于 `bun test` 的范围。
- `bun run e2e:s1-typed`：同样自动启停，复验 S1-02 至 S1-08 七课的手写填空微练习（115 项断言，每课 16 至 17 项；S1-02 要先把三个量的类型选对并走完「存文件 → 编译 → 运行」，S1-03 至 S1-07 要先选对前置公式，S1-05 还多三步提问演示与两处条件选择，S1-08 要先走完读报错/定位行/确认类型三步），覆盖脚手架只留一空、真实键盘输入、空提交/全角符号/语义错误三类失败路径、提示与参考代码兜底、重置、刷新恢复、输入内容不被当作 HTML 或正确答案、抽到的题把检查目标绑到本课学习目标原文并保留本题检查，结束后自行清理。同样需要本机装有 Chrome，且不属于 `bun test`。
- `bun run e2e:s2-typed`：同样自动启停，复验 S2-01 至 S2-08 八课的手写填空微练习（136 项断言，每课 17 项：脚手架只留一空、未走完流程不出现、真实键盘输入、空提交/全角符号/语义错误三类失败路径、提示与参考代码兜底、重置、刷新恢复、输入内容不被当作 HTML 或正确答案、抽到的题把检查目标绑到本课学习目标原文并保留本题检查），结束后自行清理。同样需要本机装有 Chrome，且不属于 `bun test`。
- `bun run e2e:s3-typed`：同样自动启停，复验 S3-01 至 S3-08 八课的手写填空微练习（136 项断言，每课 17 项，覆盖同样的脚手架只留一空、真实键盘输入、空提交/全角符号/语义错误三类失败路径、提示与参考代码兜底、重置、刷新恢复、输入内容不被当作 HTML 或正确答案、抽到的题把检查目标绑到本课学习目标原文并保留本题检查），结束后自行清理。同样需要本机装有 Chrome，且不属于 `bun test`。
- `bun run e2e:s4-typed`：同样自动启停，复验 S4-01 至 S4-08 八课的手写填空微练习（136 项断言，每课 17 项；S4-01 写干净输出 `cout << n + 1;`、S4-02 写累加 `sum += a[i];`、S4-03 写边界判断 `if (balance + x >= 0)`、S4-04 写剪枝 `if (sum > target) return;`、S4-05 写计数 `cnt[score]++;`、S4-06 写 DP 转移 `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i]);`、S4-07 写防止重复访问 `if (visited[u]) return;`、S4-08 写保底分支 `if (n <= 1000) { cout << brute(n); return 0; }`），结束后自行清理。`bun run e2e:typed` 可一次跑完 S1-02 至 S1-08、S2-01 至 S2-08、S3-01 至 S3-08、S4-01 至 S4-08、S5-01 至 S5-08 的全部 39 节已迁移课（659 项断言：S2 至 S5 每课 17 项，S1-02 至 S1-08 每课 16 至 17 项）；`CSP_E2E_LESSONS=s4-01` 可只跑一课。脚本同样复验每题把检查目标绑到本课学习目标原文、并保留一句更细的本题检查。同样需要本机装有 Chrome，且不属于 `bun test`。
- `bun run e2e:s5-typed`：同样自动启停，复验 S5-01 至 S5-08 八课的手写填空微练习（136 项断言，每课 17 项；S5-01 写按数据范围开数组 `int a[100005];`、S5-02 写分段输出 `cout << i << " " << prefix;`、S5-03 写累加变量声明 `long long sum = 0;`、S5-04 写区间和 `sum[r] - sum[l - 1]`、S5-05 写空数组保护 `if (n == 0) { cout << 0 << "\n"; return 0; }`、S5-06 写循环范围 `i <= n`、S5-07 写交叉检查的独立公式 `long long formula = 1LL * n * (n + 1) / 2;`、S5-08 写计数数组清零 `int cnt[105] = {0};`），覆盖脚手架只留一空、真实键盘输入、空提交/全角符号/语义错误三类失败路径、提示与参考代码兜底、重置、刷新恢复、输入内容不被当作 HTML 或正确答案、抽到的题把检查目标绑到本课学习目标原文并保留本题检查，结束后自行清理。`CSP_E2E_LESSONS=s5-03` 可只跑一课。同样需要本机装有 Chrome，且不属于 `bun test`。

上面每条命令的覆盖范围随课节迁移推进而变化，各课 `*-manual-checklist.md` 末尾的“自动化复验记录”表记录的是**该次复验当天**的脚本覆盖范围与结果，不是当前范围。

整课推进（`0 / N` 走到 `N / N`，外加小测本身与错题复习出口）另有一份清单：[`flow-manual-checklist.md`](./flow-manual-checklist.md)。
`bun run e2e:flow` 一次覆盖 S1-02 至 S5-08 全部 39 节已迁移课（780 项，每课 20 项），`bun run e2e:flow:s3`
这样的分段命令按阶段跑；`CSP_E2E_LESSONS=s3-07 bun tests/e2e/flow-cdp.ts` 只跑一课。

键盘可达与焦点可见（`Tab` 顺序、焦点环、弹层焦点归还、小测作答与提交后的焦点）另有清单：
[`keyboard-manual-checklist.md`](./keyboard-manual-checklist.md)。`bun run e2e:keyboard` 覆盖全部 40 课，328 项检查
（结构检查每课 8 项 + S1-02 与 S3-01 的键盘深路径每课 4 项）；只想跑一课或换两课走深路径分别用
`CSP_E2E_KEYBOARD_LESSONS` 与 `CSP_E2E_KEYBOARD_DEEP` 指定，跑的命令本身不变。

先修关系可见与可达（先修块的位置、文字、链接可达、键盘可达与手机竖屏）另有清单：
[`prereq-manual-checklist.md`](./prereq-manual-checklist.md)。`bun run e2e:prereq` 覆盖全部 40 课，
共 242 项检查（40 课各 6 项：5 项笔记本视口检查 + 1 项手机竖屏检查；另含脚本自检 2 项）；
只想跑几课用 `CSP_E2E_PREREQ_LESSONS` 指定，跑的命令本身不变。

其余课程暂无自动化脚本，仍按下面的手工步骤执行并在报告或本节记录浏览器与日期。

## 前置条件

在仓库根目录执行：

```bash
bun run dev
```

在浏览器中打开 <http://localhost:4173>。如需验证首次使用状态，先在浏览器开发者工具中删除 `csp-cpp-courseware-progress-v2`。

## E2E-01 阶段切换与课件定位

1. 打开页面，确认默认显示“第一阶段：建立程序感”和 `S1-01`。
2. 点击“第三阶段”阶段按钮。
3. 在课程列表中选择 `S4-03 模拟题专项`。
4. 使用键盘下方向键切换到下一节。

**预期：** 阶段摘要、课程列表、选中状态和详情标题同步变化；每次操作会显示即时状态提示；方向键不会在输入控件中抢走焦点。

## E2E-02 课件详情阅读

1. 选择任意一节课，例如 `S4-04 搜索与剪枝`。
2. 阅读详情中的“先修”“学习目标”“具体内容”“检验清单”“视频组织建议”“练习建议”。
3. 看“先修”那一栏：每条都写明课号、课名和那一课要会的一件事，点进去是同一节课。
4. 选中 `S1-01`，确认“先修”写的是全课程第一课、不用先修，而且没有把课号硬凑成一条链接。
5. 将筛选器切换为“只看未完成”，再切回“全部课件”。

**预期：** 每个栏目均有可读内容；“先修”排在“学习目标”之前，内容与 `index.html` 的 `courseData` 一致，链接指向真实存在的课目录；筛选改变列表而不清空已选课的内容，并显示筛选结果提示；所有状态还有文字标识，不能只靠颜色表达。

## E2E-03 进度保存与恢复

1. 选择一节未完成课件，依次勾选三个检验项。
2. 确认顶部总进度、课件状态和完成项计数更新。
3. 刷新页面。
4. 返回同一课件。
5. 点击“撤销本课完成”，再次刷新。

**预期：** 每次勾选或撤销都显示进度提示；第一次刷新后勾选项完整恢复且状态为“已掌握”；撤销后进度同步下降，第二次刷新仍保持撤销结果。

## E2E-04 浏览器存储不可用

1. 在禁用站点存储的浏览器配置或隐私窗口中打开页面。
2. 勾选任意检验项。
3. 刷新页面。

**预期：** 页面显示“进度仅保留在当前会话”的明确提示；课件导航、阅读和当前会话内勾选正常工作；刷新后不能恢复进度是可预期且被说明的行为。

## E2E-05 单课题库不可用与题目无效

1. 打开任意一节已实现课程，例如 <http://localhost:4173/lessons/s1-01/>。
2. 在开发者工具中把该页内联脚本里的 `questionPool` 临时改成 `[]`，刷新页面后进入“随机小测”。
3. 恢复题库，再把任意一题的 `answer` 改成超出选项范围的值（例如 4 个选项时写成 `answer: 99`），刷新页面后进入“随机小测”。

**预期：** 两种情况都显示“题库暂时不可用或题目无效”的说明和“无法组卷”提示，提交按钮不可点击，页面其余任务、进度与常见问题互动继续可用；不会显示伪造的分数，也不会白屏或卡住。

> S1-01 的这条场景已由 `bun run e2e:s1-01` 自动复验（脚本会自行改写题库再还原），人工只需在需要时抽查观感。

## E2E-06 会话中途保存失败与恢复

1. 打开任意一节已实现课程，例如 <http://localhost:4173/lessons/s1-01/>，先完成一次会写入进度的操作（例如点击“找到程序入口”）。
2. 在开发者工具控制台里让写入开始失败，模拟配额用尽或隐私设置变化：

   ```js
   Storage.prototype.setItem = () => { throw new DOMException("quota", "QuotaExceededError"); };
   ```

3. 继续做一次会保存进度的操作（例如选择一道随机小测的答案）。
4. 在控制台里恢复写入（执行 `delete Storage.prototype.setItem`），再点击提示里的“重试保存”。

**预期：** 第 3 步之后页面立刻出现“刷新页面后不会恢复进度”的说明和“重试保存”按钮，顶部提示条也说明这次没有保存成功；当前会话的作答与任务进度仍然保留，互动不中断；第 4 步点击重试后提示消失，顶部改为说明“本地保存已恢复”，并且第 3 步的作答被补写进本地存储。失败的写入在任何时刻都不能显示成“已保存”的分数或进度。

> 这条场景已由 `bun run e2e:s1-01`（第六个场景）在真实浏览器中自动复验，包含“失败时不把答案写成已保存”和“重试后补写落盘”两项断言。

## E2E-07 词条载入失败与恢复

适用全部已实现课程：词条面板由 [`glossary/faq-panel.js`](../../glossary/faq-panel.js) 共用，所以这条场景在任意一节课上都能复现。

1. 打开任意一节已实现课程，例如 <http://localhost:4173/lessons/s1-01/>。
2. 在开发者工具的网络面板里把 `/glossary/faq.json` 请求屏蔽（或临时把 `glossary/faq.json` 改名），刷新页面。
3. 点击课件里的一个带虚线词条，再点击右上角“常见问题”。
4. 取消屏蔽（或改回文件名），点击面板里的“重新载入词条表”。

**预期：** 第 3 步面板当场说明“常见问题表暂时无法载入，课件其他部分不受影响”，并保留“重新载入词条表”入口与“继续学习”出口；载入失败不会写成“正在载入”或已载入成功，课件其余任务、进度与小测互动照常可用。第 4 步重新载入成功后，入口收起、词条列表与解释恢复，并直接回到第 3 步点开的那个词条；如果重新载入再次失败，仍然显示失败说明并保留重试入口。

还有一种更彻底的失败：面板脚本本体就没取到（课程挂在子路径下时写死的旧地址会 404，网络中断或离线也一样）。这时页面上不会出现面板，任何词条按钮都点不出东西，所以课件页必须自己说明。

5. 把 `/glossary/faq-panel.js` 请求也屏蔽（或在网络面板里把该请求改成失败的），刷新页面。

**预期：** 页面角落立刻出现“常见问题词条这次没有载入成功”的说明，写明带虚线的词条与“常见问题”按钮暂时打不开、课件其他任务与随机小测照常可用，并给出“重新载入本课”入口；说明是 `role="status"` 且 `aria-live="polite"`，读屏也能听到。点“常见问题”按钮不会报错也不会假装修好，其余任务按钮照常工作。取消屏蔽后刷新页面，说明消失、词条恢复可点。

> S1-01 的这条场景已由 `bun run e2e:s1-01`（第七个场景）在真实浏览器中自动复验：脚本用 CDP 屏蔽 `/glossary/faq.json`，再取消屏蔽后点击重载。
> 面板脚本本体被屏蔽的情况由同一脚本的第八个场景复验：屏蔽 `/glossary/faq-panel.js` 后断言说明可见、向辅助技术播报、重新载入入口存在，且课件其他互动照常。

## E2E-08 本地开发服务器的内容边界

适用 `bun run dev` 启动的本地预览。这条场景不需要浏览器，用 `curl` 就能复验；它守的是「本地看到的」和「线上发布的那一份」不能出现两套内容。

1. 在仓库根目录执行 `bun run dev`，确认它打印的地址是 <http://127.0.0.1:4173/>。
2. 换一台设备（例如手机连同一个 Wi-Fi）访问 `http://<本机局域网 IP>:4173/`。

**预期：** 第 1 步打印的是 `127.0.0.1` 而不是 `0.0.0.0`；第 2 步连不上。默认只监听本机回环地址，仓库不会被同局域网的其他设备读走；确实需要给别的设备看时才显式写 `HOST=0.0.0.0 bun run dev`。

3. 依次请求下面这些地址，记录状态码：

```bash
curl -s -o /dev/null -w '%{http_code} /\n'    http://localhost:4173/
curl -s -o /dev/null -w '%{http_code} .git/config\n' http://localhost:4173/.git/config
curl -s -o /dev/null -w '%{http_code} wrangler.jsonc\n' http://localhost:4173/wrangler.jsonc
curl -s -o /dev/null -w '%{http_code} AGENTS.md\n'   http://localhost:4173/AGENTS.md
curl -s -o /dev/null -w '%{http_code} package.json\n' http://localhost:4173/package.json
curl -s -o /dev/null -w '%{http_code} 越界\n' http://localhost:4173/lessons/..%2F..%2Fpackage.json
curl -s -o /dev/null -w '%{http_code} 缺课\n' http://localhost:4173/lessons/s9-99/
curl -s -o /dev/null -w '%{http_code} s1-01/\n' http://localhost:4173/lessons/s1-01/
curl -s -o /dev/null -w '%{http_code} faq-panel\n' http://localhost:4173/glossary/faq-panel.js
```

**预期：** `/`、`/lessons/s1-01/`、`/glossary/faq-panel.js` 是 `200`；`/.git/config`、`/wrangler.jsonc`、`/AGENTS.md`、`/package.json`、越界地址和缺课的 `/lessons/s9-99/` 全是 `404`，响应体是中文的 `页面未找到 (404 Not Found)`，与线上 Worker 说同一句话。本地不再是把整个仓库目录当网站，`.git/` 与仓库配置不会被读走。

4. 请求少了末尾斜杠的课程地址：`curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' http://localhost:4173/lessons/s1-01`。

**预期：** `307` 并跳到 `http://localhost:4173/lessons/s1-01/`，与线上（`html_handling: "auto-trailing-slash"`）表现一致；请求不存在课程的裸地址 `/lessons/s9-99` 则直接 `404`，不会先绕一次跳转。

5. 用 `PORT=abc bun run dev`、`HOST= bun run dev` 各启动一次；再占住 4173 端口后重复 `bun run dev`。

**预期：** 三种情况都当场失败并打印中文说明（`PORT` 必须是 0 到 65535 之间的整数、`HOST` 不能为空、`PORT 127.0.0.1:4173 无法监听：端口可能已被占用`并给出 `PORT=4199 bun run dev` 的写法），不会静默换一个端口假装启动成功。

> 这条场景已由 `bun test` 里的 [`tests/dev-server.test.ts`](./dev-server.test.ts) 自动复验（8 条用例 40 余项断言：只监听 `127.0.0.1`、17 个仓库地址与 12 种越界/编码写法都拿到中文 404、站点内容与词条面板可打开且带 UTF-8 类型头、目录地址 307 跳转与缺课 404、内容清单与构建共用同一份定义、坏 `PORT`/`HOST`/端口占用当场失败）。手工步骤保留下来，用于换机器或换网络后复核这条边界仍然成立。
