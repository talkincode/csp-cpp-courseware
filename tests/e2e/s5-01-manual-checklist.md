# S5-01 手工端到端验收

在仓库根目录运行 `bun run dev`，打开 <http://localhost:4173/lessons/s5-01/>。如需从头开始，删除浏览器本地存储键 `csp-cpp-s5-01-progress-v1` 后刷新。

## E2E-S5-01-01 引导任务推进

1. 在任务 1 为“40 分钟训练只做一道题。拿到题后第一步该做什么？”选择“先审题计时：圈数据范围、看样例，并记下这道题大概花多少分钟”，为“代码刚写完，样例还没对照过，该怎么做？”选择“先用样例输入核对输出，再考虑提交”。先故意选一个错误说法。
2. 在任务 2 依次点击“审题：圈范围并记下时间预算”“草稿：写下已知、未知和打算”“对照：编码后先跑样例再提交”。尝试跳过第一步直接点第二步。
3. 在任务 2 出现的只读脚手架里亲手补空：`int a[` 与 `];` 之间那一格要写审题圈出的 `n ≤ 100000` 对应的格子数。先空着点“检查这一空”，再输入全角写法 `int a［100005］；`，再输入正好 `int a[100000];`，最后写对 `int a[100005];`。
4. 在任务 3 先选择一个错误说法，再选择“比赛结束前留出几分钟，重新对照样例并看边界”，以及“不跳过样例：输出必须和样例完全一致，再考虑边界”。

**预期：** 每一步都显示即时文字反馈；下一任务仅在前一任务完成后点亮；错误选项解释为什么直接敲代码、把样例留到最后、跳过样例、先开下一题、写完立刻提交、样例对了就不用测边界都有风险；对照卡片从“还没开始审题计时”变为已审题计时，再变为已写好建模草稿，最后变为“已对照样例，准备做提交前检查”；页面标明必会、建议掌握和拓展；手写那一空答对后给出“进入任务 3”的反馈；正确完成会出现奖励提示，音效关闭时仍有完整视觉反馈。页面不运行学习者提交的 C++，也不加载视频。更细的分钟级时间片只作为拓展出现。

补充：任务 2 三步没点完时输入框不出现；点击尚未点亮的任务，或跳过“审题：圈范围并记下时间预算”“草稿：写下已知、未知和打算”直接点“对照：编码后先跑样例再提交”时，页面必须解释当前缺少哪一步，不能无反馈；三步走完并且那一空答对之后，任务 3 才点亮，任务 3 两个选择都答对后任务 4（随机小测）才点亮。空提交、全角符号、写成 `int a[100000];`（差一格会在下标 100000 越界）、写成 `int a[n];`（格子数不能用变量）、漏掉 `int` 或末尾分号，都只给具体指正，不算完成。

## E2E-S5-01-02 随机小测与解析

1. 进入“随机小测”，确认显示本次试卷标识和 3 道选择题。
2. 不作答时确认提交按钮不能提交；选择三题答案后提交。
3. 阅读每题解析和总分。
4. 点击“换一套题”。

**预期：** 单次试卷题目不重复；每题都有课程目标、四个选项、一个正确答案和解析；选择题数量多于非选择题；提交后显示逐题正误与得分；换题后试卷标识变化且不保留上一套答案。题库来源为本课 course-plan / 自编，并标记待人工审校。

## E2E-S5-01-03 恢复与降级

1. 完成任意任务或选择部分小测答案后刷新页面。
2. 回到当前任务，确认状态选择、三步操作和答案恢复。
3. 在禁止站点存储的浏览器环境中重复一次操作。

**预期：** 正常环境能恢复任务、试卷与答案；存储不可用时页面明确说明“刷新后不会恢复进度”，页面不会卡住或伪造保存成功。

## E2E-S5-01-04 常见问题解惑

1. 在任务 1 点击带虚线的 `限时解题流程`、`审题计时` 或 `样例检查`。
2. 确认侧栏出现基础解释、一句“现在记住”和至少一个外部链接。
3. 关闭后回到任务 2，确认页面仍可继续，并在脚手架旁点击 `数据范围`、`越界`。
4. 再点右上角“常见问题”，切换到 `限时解题流程`、`建模草稿`、`预留检查时间`。

**预期：** 解释只用初学者能懂的话；不要求背完整的赛场规则或分钟级时间片；外部链接在新标签打开。词条以小卡片出现，不挡住任务按钮；点遮罩、“关闭”或“继续学习”后可立刻继续做题。

## 自动化复验记录

E2E-S5-01-01 中的手写填空部分可以在真实浏览器中自动重跑一遍，不需要人工点击：

```bash
CSP_E2E_LESSONS=s5-01 bun tests/e2e/s2-typed-cdp.ts
```

脚本会自行启动开发服务器（`bun scripts/dev.ts`）和无头 Chrome，结束后关掉自己启动的进程并删除临时配置目录。它需要本机装有 Chrome；若换成别的可执行文件路径，用 `CSP_E2E_CHROME` 指定。它不属于 `bun test`：断言依赖真实浏览器渲染，属于体验验收而不是单元测试。`bun run e2e:s5-typed` 会一次覆盖 S5-01 至 S5-08 八课（112 项检查），`bun run e2e:typed` 覆盖全部 32 节已迁移课（448 项检查）。

| --- | --- | --- | --- |

自动化覆盖的部分：输入框等宽字体与移动端防干扰属性、脚手架只留一空（本课是 `int a[` 与 `];` 之间那一格）、任务未走完不出现输入框、逐字符真实键盘输入会写进草稿、空提交与全角符号与写得差一格的指正、提示与参考代码与重置兜底、作答正确后进入任务 3、刷新后草稿与完成状态恢复、输入内容原样保留且不会被当成 HTML 或正确答案。仍需人工确认的部分：窄屏排版、键盘焦点观感、音效听感，以及 E2E-S5-01-02 到 -04 的场景。
