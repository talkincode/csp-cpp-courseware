# CSP C++ Courseware 项目画像与方向

## 项目概述

本项目把“信息学长期递进学习”落到一套面向零基础学习者的 C++ 在线课程中，目标为 CSP-J 入门到提高。当前静态页面用于确认五阶段、40 节课程的规划；40 节课程均已拥有自己的互动学习界面和随机在线测试（题库与解析已通过机器校验，证据见 `docs/review/question-verification.json`）。视频课件由仓库外流程制作，本仓库只负责代码功能与课程事实对齐。

```text
学习者
  |
  v
当前课程路线原型（index.html）
  |-- 五阶段 / 40 课的课程数据
  |-- 目标、内容、检验清单、练习建议
  `-- 浏览器本地进度（localStorage）

单课在线学习单元（40 课已实现）
  |-- 本课互动学习界面
  `-- 本课随机在线测试（选择题为主、含解析）

仓库外的视频课件交付
  `-- 与课程 ID 对齐的视频、章节与文字稿

内容维护者
  |-- docs/course-plan.md
  |-- docs/feature-checklist.md
  `-- AGENTS.md 内容与验收规约
```

## 项目画像（目标状态）

完成后的课程应像一份由竞赛教练持续维护的训练工作台：初学者能在任意一节课迅速知道“为什么学、这一节具体学什么、做成什么才算会”，然后在同一课程单元中完成互动学习和自测，而不是被概念或题库淹没。五阶段路线提供稳定的长期方向；每一课都可以独立用于课堂讲授、自学和仓库外视频制作。

价值优先级是：**概念正确与年龄友好** 高于内容炫技，**可验证的掌握** 高于完成视频数量，**题目与解析质量** 高于随机性的表面新鲜感，**低门槛与长期可维护** 高于复杂平台功能。课程要始终诚实标注 CSP-J 的边界：不能以“竞赛”之名承诺保奖、保过或提前灌输不适合初学者的高级内容。

- **单课件学习面板**：`index.html` 的课件详情会显示每节课的学习目标、具体内容、检验清单、视频组织建议和练习建议。

- **整课推进浏览器自动化复验**：`bun run e2e:flow` 用无头 Chrome 与 CDP 把 S1-02 至 S5-08 全部 39 节已迁移课从 `0 / N 已推进` 走到 `N / N`（741 项，每课 19 项）：跳步会被拦住、每一步都经过真实浏览器点击、完成时给出可见文案、刷新后进度仍在、清掉本地存储就回到起点，并趁小测面板可见时量「检查目标绑到本课学习目标原文、没答完不能提交、提交后才给解析与得分、没考住时按学习目标汇总错题并指回本节讲解且不倒退进度」；走完 `N / N` 后再量「没做完之前继续学习入口是隐藏的」与「入口打开后写明下一课是 `Sx-xx` 与课名、直达下一课且真的可达（`HEAD` 请求验过），最后一课换成课程收尾出口」。脚本以页面自己的 `unlockedStepCount()`为进度准绳、只在空位真的露出来时才填、按组试互斥选项而不是全点一遍，答案表与 `bun run e2e:typed` 共用 `tests/e2e/lesson-flows.ts`；它不属于 `bun test`：断言依赖真实浏览器渲染，属于体验验收而不是单元测试。
- **课后继续学习入口**：39 节非末课在走完 `N / N` 后由页面自己打开 `#nextStep`：写明下一课是 `Sx-xx` 与课名、先练的那件事（首条学习目标原文），链接直达下一课的 `index.html`，并再次说明进度只保存在这台设备的浏览器里。没做完之前这个入口是隐藏的，不会把还在这一课上的学习者提前引走。S5-08 是最后一课，入口换成课程收尾：说明五阶段 40 课已经走完、建议怎么复盘、题目与解析已通过校验，并指回课程路线；这里不给成绩评定、证书或任何能力认证的说法。`tests/next-lesson.test.ts` 逐课锁住这条契约（下一课按 `courseData` 顺序推导，标题与前一条学习目标必须与课程数据逐字一致，链接文件必须存在，导航必须排在「视频边界」说明之后），`bun run e2e:flow` 在真实浏览器里复验同一条路径。

## 非目标（铁律）

- 不把本项目建设为在线判题系统、代码云执行平台或题库爬虫。
- 不把 CSP-S、NOIP、NOI 的高级算法作为 CSP-J 初学者的隐性必修内容。
- 不要求账号登录，不采集未成年人姓名、学校、联系方式、学习画像或公开排名。
- 不提供标准答案堆砌；课件必须优先解释思考过程、边界条件和自测方法。
- 不把“随机出题”理解为临时拼接或未经校验的生成式题目；正式试题、答案和解析必须可追溯、可复现。
- 不依赖付费 SaaS、专有运行时或复杂构建链才能阅读课程入口；在线视频与测试资源可以在线发布，但资源不可用时必须有明确状态与恢复路径。

## 方向与意图

### 每课专属在线学习单元

每一个 `Sx-xx` 都应从课程目录中的一条记录成长为可独立完成的在线学习界面：学习目标、互动讲解、最小示例、思考提示、课内检验与下一步入口都围绕该课组织。学习者可以按路径连续学习，也能从链接直接进入某一课而不丢失上下文。

### 仓库外视频课件交付

每一个在线学习单元可与目标完全对应的外部视频课件相连。视频不是网页文字的无差别朗读：它要承担演示代码运行、拆解思考过程、展示常见错误或引导练习中的至少一种不可替代作用，并配有章节定位和字幕或文字稿。本仓库不实现视频生产、存储、转码或播放；只保证课程 ID、目标和外部交付状态能够准确对齐。

### 随机在线测试与有效复习

每节课应提供可重复参加的在线测试。每次测试从已审校、带目标标签的问题库中抽取不同题目；选择题严格占多数，但可以保留少量适合该课的非选择题。随机过程要可复现，同一次尝试不得重复出题，提交后必须显示得分、逐题解析及指向薄弱目标的复习出口。测试要测“是否理解本课”，不能以陌生难题替代教学。

### 课程事实与质量控制

目标、互动内容、视频元数据、题库和解析应保持一条可追溯的课程事实链。课程目标变更时，相关互动步骤、视频章节、测试题和解析均需要检查，不得出现“课程讲 A、测试考 B”或“目录写 A、视频讲 B”的漂移。

### 保留低门槛入口

在线发布应让学习者随时进入课程，而不是迫使其先注册或交出个人资料。首版仍以无账号、无排行榜、无在线代码执行为边界；如果日后确有必要引入身份或教师功能，必须先修改项目边界并补齐权限、隐私和双角色验收。

## 完成的样子

- 任何一节课都能在一分钟内看出它的先修关系、目标、互动学习入口、检验方式和练习出口；如有外部视频交付，也能看出它与课程的对应状态。
- 零基础学习者能从第一阶段开始，逐步完成第四、第五阶段的 CSP-J 专项与模拟，而不必猜测下一步该学什么。
- 每节课的网页互动在桌面和手机上均可完成；资源加载、操作成功、失败与恢复状态都能被学习者理解。
- 外部视频课件可以定位到对应知识点，并提供字幕或文字稿；本仓库不会把视频资源异常伪装为“已完成”状态。
- 每次在线测试都能生成不重复的有效试卷，选择题占多数，提交后给出可验证的得分、解析和复习出口。
- 内容维护者新增或调整课程时，会同时检查课程规划、互动内容、视频元数据、题库、功能清单和验收矩阵；结构错误会被自动校验挡下。

## 维护规则

- 代码、可运行校验和手工验收记录是当前能力的事实来源；文档与它们冲突时，先标注文档需修订。
- 新需求进入前先检查是否违反“非目标（铁律）”；若违反，必须先由项目负责人显式改变边界。
- 新增一级功能时，同步新增 Happy Path E2E、更新本矩阵，并满足适用的失败/权限/恢复覆盖底线。
- 课程从“规划”变为“在线可学习”时，互动界面、测试、题库元数据及其验收证据必须一起到位；缺一项就只能标为规划。视频课件由仓库外流程管理，不作为本仓库实现状态的前置条件。
- 题库、答案、解析和随机组卷规则变更时，必须重新验证同次无重复、选择题占多数、检查目标与 `courseData` 学习目标的绑定（`objectiveIndex`、讲义里的目标副本、`lesson.json` 的覆盖数据）、答案正确性和可复现性。
- 发布静态站点只走 `bun run deploy` 生成产物（它内部会先 `bun run build`）；main 上的推送由 `.github/workflows/test-and-deploy.yml` 自动完成「`bun test` → 发布 → 线上抽检」，人工发布是它不可用时的兜底。不得手工拼装 `dist/` 或发布未提交的改动，线上内容必须等于仓库的构建结果。
- 只有目标画像、边界或一级能力变化时才更新本文档；日常任务进度不应污染项目画像。
